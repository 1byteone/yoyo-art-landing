# 原站与前端实现解析

## 1. 目标与边界

- 参考目标：[Oil UI Art Landing](https://ui.oiloil.org/art-landing/)。
- 当前项目：YOYO Art Landing，一个以模块化视觉和交互实验为主题的独立品牌页面。
- 目标不是把当前页面称为像素级克隆，而是把原站的布局、叙事、图像层级和运动实现拆成可检验的前端规格，并说明哪些细节已转译、哪些因为品牌/素材不同而保留差异。
- 若要做真正的原站级复刻，应使用 `prompts/PIXEL_ACCURATE_RECONSTRUCTION.md` 并提供 `docs/REFERENCE_ASSET_CHECKLIST.md` 中的素材；不能用 YOYO 图像假装是原站资产。

## 3. 原站页面结构与阅读节奏

### 3.1 全页信息架构

1. **品牌导航**：Oil UI 标识、语言/账户入口、插件/开源版/Pro 链接；承担品牌和产品入口。
2. **Hero / 视觉承诺**：产品附赠标识、艺术化官网标题、一段说明、购买与实机预览两个 CTA；同屏图片轨道开始展示真实案例。
3. **差异解释**：解释画面、克制排版和真实产品界面为什么需要作为一个整体设计。
4. **风格演示与页面一致性**：使用状态切换说明整页同调、避免不同区块像来自不同模板。
5. **行业适配**：金融/企业服务、AI/开发者工具、协作/消费产品三个方向展示不同视觉气质。
6. **真实案例档案**：W01–W20 共 20 项，类别筛选为异境风光、暗房与光学、版画与纸本、器物与超现实，每类 5 项。
7. **产品转化**：说明 Oil UI Pro 的授权/交付内容并提供购买 CTA。
8. **页脚**：收束品牌、页面和产品导航。

页面叙事采用 **Promise → Proof → Application → Library → Conversion**：先给出明确承诺，再提供风格和行业证据，之后用可筛选案例库证明覆盖能力，最后转化。长页不是把卡片堆起来，而是把“为什么有效”逐步论证。

### 3.2 Hero 的构图职责

- 导航栏单行、浅色背景；Hero 主标题为高对比衬线字，文案宽度受到约束，两枚 CTA 排列在标题下方。
- 主视觉不是一张静态封面：三条斜置作品轨道以相反方向运动，形成横跨屏幕的连续图像墙。
- 每张卡片像一张网页预览，而非普通产品 UI 卡；统一宽高比、窄间距和一致阴影建立“案例墙”的阅读节奏。
- 植物/环境图像处于较低对比度前景，与轨道发生边缘遮挡；它提供空间深度，也把视觉重心压在 Hero 下沿。
- 文案层、运动轨道、透明前景、按钮与元信息各有层级；不能把所有东西压成一个背景图，也不能让图片遮挡标题/CTA。

### 3.3 历史测量的几何参数

仅限历史 **1440×900** 浏览器证据。整数为近似整理值，具体元素、滚动位置和状态需以原始测量记录为准。

| 属性             |                   历史记录 | 实现意义                           |
| ---------------- | -------------------------: | ---------------------------------- |
| Header 高度      |                       56px | 为首屏主构图提供稳定上沿           |
| Hero 起点 / 高度 |             y=56px / 844px | 首屏主体约占 Header 以外的完整视口 |
| 图片卡片         |                  256×160px | 约 1.6:1 的网页预览盒              |
| 卡片间距         |                       14px | 低间距保证图像墙连续而不糊成一片   |
| 图像墙倾角       |                        -8° | 产生贯穿屏幕的斜向运动轴线         |
| 轨道方向         |               左 / 右 / 左 | 三轨速度与方向错开，避免同步平移   |
| 轨道水平速度     | 约 36 / 32.3 / 36 CSS px/s | 不以固定秒数硬套所有图像总宽度     |

项目内的 `docs/reconstruction/REFERENCE_MEASUREMENTS.md` 记录更细的历史 DOM 数据、采样状态和测量限制。原站会持续更新；进行新一轮复刻时应重新采样，而不是把上述历史数值无条件当作当前线上值。

## 4. 原站方法到当前页面的映射

| 原站机制                | 当前 YOYO 版本                                     | 保留/改变原因                                  |
| ----------------------- | -------------------------------------------------- | ---------------------------------------------- |
| Editorial art direction | 紫、荧光绿、纸白、墨色与等距模块插画               | 复用“整页统一艺术指导”的方法，品牌语汇重新设计 |

## 5. 前端术语与工程实现

### 5.1 语义 DOM 与组件架构

- **Semantic HTML**：页面由 `header`、`nav`、`main`、`section`、`footer` 组成；导航目的使用 `a`，触发状态变化使用 `button`，筛选输入采用原生表单控件。
- **Component composition**：`App.tsx` 编排页面章节；`HeroGallery` 管文案和全宽主视觉；`HeroImageWall` 管轨道、前景和控制；各章节实验独立封装在 `src/components/`。
- **Data-driven UI**：案例、资产、行业和工作流内容位于 `src/data/`，列表由数据生成，筛选/计数不靠手工重复写死。
- **Single source of truth**：类别、场景 ID、文件路径、自然宽高和用途进入资产数据表；替换素材时同步检查其 `object-fit` 和透明属性。

### 5.2 CSS 布局与设计令牌

- **CSS Grid**：宽屏画廊使用 12 列并以跨列数构造错落节奏；手机重组为两列。它比给每张卡片单独设置绝对坐标更易维护。
- **Flexbox**：用于导航、CTA、筛选工具条、卡片元信息与横向无缝轨道。
- **Custom properties / design tokens**：颜色、内容宽度、间距、字号、层级和 Hero 轨道卡片宽度放在 `design-tokens.css`、`tokens.css` 与 Hero 作用域变量中；避免每个区块出现不受控的相近色值。
- **Responsive composition**：900px 以下改变主内容组织，700px 以下使用移动端构图，380px 以下进一步收紧标题/按钮。断点属于本地项目规格，不是原站断点的声称。
- **Intrinsic sizing**：卡片使用固定宽度变量和 `aspect-ratio`；场景图片使用 `object-fit: contain` 保全画面，不因裁切丢掉等距插画边缘。
- **Layering / stacking context**：Hero 壁画使用独立裁切与层级；透明前景位于轨道上方，控件处于前景层上方。新建 `transform`、`isolation` 或 `overflow` 时须重新验证堆叠和裁切。

### 5.3 无缝轨道动画

实现路径为 `HeroImageWall.tsx` + `hero-marquee.css`：

1. 每轨渲染一组可交互卡片，再渲染一组 `aria-hidden` 的视觉副本；两组同宽，循环末尾可直接接回开头。
2. CSS `@keyframes` 将 track 移动半个总轨宽；第二条方向反转，轨道之间再用不同 delay 错开相位。
3. `ResizeObserver` 读取真实卡组宽度。周期根据投影距离和目标水平 CSS px/s 计算，因此视口/卡片尺寸变化时速度仍近似稳定。
4. 统一的暂停状态通过 `.hero-marquee--paused` 控制所有轨道；暂停后必须验证 `animation-play-state: paused`，不能只变图标或 `aria-pressed`。
5. 监听 `prefers-reduced-motion`：系统偏好减少动态时关闭运动并给出清晰控件状态。

避免用 JavaScript 定时器逐帧移动每张卡片；这会扩大状态面、增加布局/合成压力，并让无缝循环更难校准。

### 5.4 滚动动效与可访问性

- **IntersectionObserver**：`ScrollReveal.tsx` 只在内容第一次进入视口时揭示，随后取消观察，避免重复触发。
- **requestAnimationFrame**：被动滚动监听只提交一次待处理帧，帧内集中测量元素并更新 `translate` 偏移，减少高频事件中的重复 layout。
- **Reduced motion**：媒体偏好变化时断开 observer 和事件监听、取消未执行帧，并清除位移变量；不是单纯把 transition 时间设为 0。
- **ARIA state**：tabs 用 `aria-selected`，切换按钮用 `aria-pressed`，移动导航用 `aria-expanded`，视图变化由可读标签表达。
- **Dialog**：作品预览使用原生对话框语义，支持关闭按钮和 Escape；焦点可见且控件可键盘操作。
- **Alt/图片副本**：轨道副本对辅助技术隐藏，装饰性图片用空 alt；可点击主卡片使用明确的场景名称。

### 5.5 素材工作流与性能

- 当前主图是 4×4 联系表中裁切出来的 16 个 384×256 WebP，不得声称是 16 张独立高分辨率原图。
- 前景透明 PNG/WebP 保留 Alpha；布局必须通过 `width/height` 比例、自然宽高和真实透明区域共同校准。
- 图片进入展示状态时检查 `complete`、`naturalWidth` 和 `decode()`；对不同宽高比使用资产级适配，不用全局 `cover` 把主体裁掉。
- 生产构建由 Vite 静态输出到 `dist/`；当前没有服务端 API，也不需要后端运行时。

### 5.6 自动化验证

`npm run verify` 覆盖类型、Lint、格式、Playwright 交互和视觉视口检查；`npm run build` 验证可发布静态产物。关键门槛：无横向溢出、五种视口的 Hero 画廊全宽、首排在首屏出现、素材加载成功、轮播暂停状态真实生效、减少动态偏好可用。

自动截图适合发现几何和状态回归，但无法代替人工检查字体气质、插画语义、焦点层级、运动观感和真实目标站的当前状态。

## 6. 诚实的差距说明

- 当前项目的品牌、文字、行业案例、CTA 和图像内容与原站不同，所以整体像素差异是预期结果。
- 384×256 的联系表裁切图不等同于原站高分辨率网页预览；CSS 不能恢复缺失细节。
- 三种 YOYO 前景不是原站植物图像；透明边缘、景物和背景细节无法通过调 opacity 补足。
- 历史原站视觉记录以一个桌面视口为主；除非补充实时采样，不对其他宽度宣称像素级一致。
- 真正像素级重建前，先取得授权可用的原始素材、各断点截图、完整页面截图和关键状态录屏，然后按 Prompt 做同视口差分闭环。
