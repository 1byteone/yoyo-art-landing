# 响应式规范

本文件记录本地实现断点与测试覆盖，不将桌面样式按比例缩放到手机，也不声称这些断点来自参考站实测。

## 断点策略

| 宽度规则 | 主要策略                                                                                        |
| -------- | ----------------------------------------------------------------------------------------------- |
| ≥1700px  | 扩大 Hero 画布比例与两栏间距，内容宽度仍有限制                                                  |
| ≤1100px  | Hero 调整为更紧凑列宽；资产网格减少列数；应用预览控件收缩                                       |
| ≤900px   | Hero、视觉工作区、构图实验、行业预览等主要双栏结构转为纵向；构图图层控制重新排列                |
| ≤700px   | 移动导航启用菜单；Hero 文案/画布纵向排列；画廊转为 2 列；筛选计数独占行；摘要和实验控件重新排布 |
| ≤380px   | Hero 标题、按钮和画廊标题进一步收紧，避免窄屏横向溢出                                           |

## 视口验证矩阵

| 视口        | 类型     | 自动检查                                      |
| ----------- | -------- | --------------------------------------------- |
| 1920 × 1080 | 宽屏桌面 | 页面无横溢；12 栏作品网格；主要章节存在；截图 |
| 1440 × 900  | 标准桌面 | 同上；另有完整页面截图                        |
| 1280 × 800  | 紧凑桌面 | 同上；非对称网格与内容宽度约束                |
| 768 × 1024  | 平板竖屏 | 主布局叠放、12 栏细分网格、视口无横溢         |
| 390 × 844   | 手机     | 移动菜单和 2 栏作品网格；完整长页截图         |

Playwright 默认 Chromium 设备像素比为 1，页面缩放保持默认值。截图前等待字体 API、强制图片 eager 并 await decode；使用 reduced-motion 固定入场与滚动状态。

## 内容安全约束

- 全局最小 body 宽度为 320px；本轮自动化矩阵最小实测宽度是 390px，不能把 320px 的代码约束等同于 320px 完整验收。
- 作品网格在手机为两列，但每第五项可跨满宽度；桌面由 12 栏 span 形成错落节奏。
- Hero 的文案先于大画布出现，手机不让高宽场景挤压标题和 CTA。
- dialog 在手机改为上下结构，主图、标题、元数据和关闭按钮保持可视。
- 所有页面级段落使用固定间距上下限；导航、按钮和编辑器控件使用稳定的最小高度。

## 后续校验建议

新增断点或改变卡片跨度时，更新 tests/visual.spec.ts 的视口与列数断言，再重新检查 artifacts/after/yoyo-final/ 的桌面、平板、手机截图。横向无溢出只是底线，不替代文字包裹和视觉重心人工检查。
